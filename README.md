# OLAX F90 band manager

CLI для Linux, который сравнивает LTE-диапазоны USB-модема **OLAX F90**,
выбирает лучший по скорости и качеству соединения и применяет его.
Замеры выполняются **напрямую через модем, без VPN**.

## Возможности

- Чтение текущего Band, статуса LTE и сигнала через веб-API модема.
- Последовательный scan поддерживаемых диапазонов с несколькими замерами
  на каждый Band и сравнением медиан download/upload/ping/loss/jitter.
- Применение победителя; lock от параллельных операций и возврат на исходный
  рабочий Band при прерывании или критической ошибке.
- Проверка source IPv4 OLAX, маршрутов контрольного адреса и сервера до,
  во время и после передачи, адресов соединения и байтовых счётчиков модема.
- Локальные JSON/CSV-результаты и промежуточный progress после каждого Band.
- `doctor` и `--dry-run` для проверки конфигурации без обращений к модему.

Wi-Fi можно оставить подключённым, если маршруты измерительных адресов идут
через OLAX. Скрипт отклоняет путь через Wi-Fi/VPN; самостоятельно маршруты,
VPN, настройки рабочего стола и прошивку не меняет.

## Требования

- Linux и Python **3.10+**; Python-код использует стандартную библиотеку.
- `curl` с поддержкой `--write-out '%{json}'` (7.70+), `ip` из iproute2,
  `ping` из iputils.
- USB-сетевой интерфейс OLAX и доступ к его панели (обычно `192.168.100.1`).
- Пароль панели для авторизации и переключения диапазонов.

Дополнительный backend `speedtest` использует установленный Python
`speedtest-cli`; для основного Cloudflare-backend он не нужен.

## Установка

```bash
git clone https://github.com/kissabmi/olax-f90-band-manager.git
cd olax-f90-band-manager
cp .env.example .env
chmod 600 .env
```

Отредактируйте `.env`, сохранив пароль только в этом локальном файле:

```dotenv
F90_BASE_URL=http://192.168.100.1
F90_USERNAME=admin
F90_PASSWORD=your-modem-password
F90_OLAX_INTERFACE=your-usb-interface
F90_SPEEDTEST_BACKEND=cloudflare
```

Имя интерфейса определите через `ip -br address`; например, оно может
выглядеть как `enp0s20f0u4`. После смены USB-порта проверьте его заново.
Вместо `F90_PASSWORD` можно задать `F90_PASSWORD_FILE` — путь к локальному
файлу пароля с правами `600`. Реальная `.env` исключена из Git.

```bash
./f90-band doctor
./f90-band scan --dry-run
```

Эти команды не отправляют запросов к модему и не запускают сетевой замер.

## Сравнение диапазонов

Если активен VPN с kill switch, отключите его перед прямым тестом.
Сначала проверьте регистрацию LTE и прямой путь:

```bash
./f90-band status
./f90-band path
./f90-band benchmark --tests 1
```

`benchmark` измеряет текущий Band без смены настроек и сохраняет
`results/current.json`. Если путь не подтверждён через OLAX, тест не принимается.

Полный scan с двумя замерами каждого доступного Band:

```bash
./f90-band scan --bands 3,1,7,8,20,28,38,40,41 --tests 2 --allow-disruption
./f90-band status
```

**Каждая смена Band перезагружает модем и ненадолго обрывает его соединение.**
`set`, `scan` и `auto` требуют `--allow-disruption`; без него они завершаются
до обращения к модему. Список диапазонов должен соответствовать прошивке
и задаётся `F90_BANDS`. При необходимости начните с текущего Band.

Скрипт проверяет доступность измерительного endpoint перед записью в модем,
ждёт LTE именно на запрошенном Band, измеряет скорость и печатает таблицу.
Диапазоны без LTE или с неудачным замером получают `unavailable` с причиной.

### Как выбирается победитель

Основной критерий — максимальная **медиана download** среди доступных Bands
с приемлемыми потерями и ping (по умолчанию ≤10% и ≤200 мс).
В группе, отстающей от максимума не более чем на 15%, выбирается лучшее
качество: loss, ping, jitter, затем SINR, upload и download.
Победитель автоматически применяется.

Для уточнения близких результатов или повторения единичной сетевой ошибки:

```bash
./f90-band scan --bands 7,8,3 --tests 3 --allow-disruption
```

Лучший Band зависит от места, сигнала и нагрузки сети. Повторяйте сравнение
при изменении условий; результат одного scan не является постоянной гарантией.

## Метод измерения

По умолчанию `F90_SPEEDTEST_BACKEND=cloudflare` использует
`speed.cloudflare.com` через HTTPS. IPv4 endpoint закрепляется на весь scan.
Каждый sample скачивает **8 MiB** и отправляет **2 MiB** случайных тестовых
байт; перед scan выполняется небольшая readiness-проба. Размеры одинаковы
для всех Bands, timeout одной передачи — 90 секунд.

Curl привязан к IPv4 OLAX, proxy, curlrc и redirects отключены. Проверяются
HTTP 200, точные объёмы, local/remote IP, обычные и source-bound маршруты,
стабильность пути и прирост счётчиков USB-интерфейса. ICMP ping дополняет
скорость показателями задержки, jitter и loss.

Это **одиночные HTTPS-передачи с учётом всей длительности**, а не многопоточный
Ookla Speedtest и не теоретический предел LTE. Явный
`F90_SPEEDTEST_BACKEND=speedtest` выбирает прежний `speedtest-cli`;
его binary/ID настраиваются через `F90_SPEEDTEST_BINARY` и
`F90_SPEEDTEST_SERVER_ID`. Доступность стороннего сервиса может отличаться
между сетями и операторами.

## Результаты и восстановление

Локально сохраняются:

| Файл | Содержание |
|---|---|
| `results/current.json` | Последний замер текущего Band |
| `results/latest.json` | Последний завершённый scan и применённый победитель |
| `results/history.csv` | История сравнений |
| `results/scan-progress.json` | Частичные результаты и состояние scan |
| `state/last-good.json` | Последний известный рабочий Band |

Папки можно перенести через `F90_RESULTS_DIR` и `F90_STATE_DIR`. JSON/CSV и
конфигурация сохраняются с правами `600`; результат содержит доказательства
прямого пути. Исторические неподтверждённые/VPN-замеры не используются как baseline.

При критической ошибке или `Ctrl+C` scan пытается вернуть исходный рабочий
Band. Частичные данные сохраняются как `aborted`, а не выдаются за завершённый
`latest.json`. Параллельные `set`, `scan` и `benchmark` блокируются через `flock`.

Для отдельной живой проверки fail-safe зафиксируйте исходный рабочий Band,
начните scan другого уже проверенного диапазона и после смены Band и возврата
LTE нажмите `Ctrl+C` **один раз**. Дождитесь `Restored B<исходный>` и проверьте
`status`/`path`. Успешный обычный scan не заменяет эту проверку прерывания.

## Другие команды

```bash
./f90-band raw-get lte_band lte_rsrp nv_pci nv_arfcn
./f90-band set 7 --dry-run
./f90-band set 7 --allow-disruption
./f90-band auto --dry-run
```

`status`, `raw-get` и `path` настройки не меняют. `auto` делает health-check;
после двух плохих проверок запускает shortlist, затем полный scan, если shortlist
не дал рабочего варианта. Обычные HTTP warm-up/probe отключены:
`F90_WARMUP_URL` и `F90_PROBE_URL` должны оставаться пустыми.

## Опциональный systemd timer

В `systemd/` лежат шаблоны, которые **не устанавливаются автоматически**.
В `f90-band-manager.service` измените `WorkingDirectory` и `ExecStart`
под расположение своего checkout; `EnvironmentFile` — под локальную конфигурацию.
Автозапуск включайте отдельным решением только после живых проверок
`status`, `set`, `benchmark`, `scan` и успешного fail-safe при прерывании.

## Протокол модема

Используется ZTE-подобный API: `GET /reqproc/proc_get`,
`GET/POST /reqproc/proc_post`. Для применения Band отправляется
`SET_FREQ_BAND` с восьмибайтовой маской `work_lte_band`, затем
`REBOOT_DEVICE`. Для B7 маска — `64,0,0,0,0,0,0,0`, не номер диапазона.
Маски переопределяются через `F90_BAND_MASKS`.

Авторизация пробует nonce, затем legacy base64. При отличиях прошивки сравните
запрос применения Band в Network браузера с программой. Доступны
`F90_AUTH_MODE`, `F90_WRITE_MODE`, `F90_STATUS_COMMANDS` и `F90_BAND_MASKS`.
Несвязанные настройки и прошивка не изменяются.

## Проверки

Для offline-тестов установите `pytest` и `ruff` в своей среде, затем:

```bash
python3 -m pytest -q
ruff check src tests
python3 -m compileall -q src main.py f90-band
```

Текущая версия проверена 191 offline-тестом и реальным scan девяти диапазонов
на OLAX F90. Проверки маршрута и выбор победителя прошли независимое review.
В одном тестовом размещении B7 оказался быстрее B8/B3; это пример результата,
а не настройка, подходящая всем. Локальные пароли, исходные результаты замеров,
захваты модема и история рабочих сессий в публичный репозиторий не входят.
